# GTT 0.1.61 — Win64 Candidate Qualification & Authored Trailer Import

## Added
- Added an exact-candidate authored-trailer import gate to the canonical UE 5.8 Win64 evidence workflow, before packaging.
- Added `AUTHORED_TRAILER_IMPORT.json`, bound to the exact commit SHA and project version, and carried it through the technical-candidate artifact and reviewed-release gate.
- Added `Scripts/run_win64_candidate_acceptance.ps1`, a fail-closed one-command Windows qualification path that can execute the same import/package/runtime/rendered-evidence chain on a UE 5.8 workstation even before it is registered as a self-hosted Actions runner.
- Added `WIN64_ACCEPTANCE_SUMMARY.json` for the exact technical candidate; it records the PASS evidence while explicitly keeping human visual review required and Demo Release unauthorized.
- Added deterministic source verifiers and dedicated CI that lock package/import/runtime/visual/release ordering plus the local/runner acceptance contract.
- Added a real `ProjectVersion=0.1.61` source of truth so manually dispatched package/release jobs cannot silently publish a stale or mistyped candidate label.
- Added a dedicated acceptance/playtest contract covering positive and fail-closed Windows candidate cases.
- Added `Scripts/write_win64_candidate_attestation.ps1`, which fail-closes on SHA/version/configuration drift, validates schema-17 technical and rendered evidence, hashes the packaged `GTT.exe` plus critical evidence/screenshots, writes `WIN64_CANDIDATE_ATTESTATION.json`, then creates `FINAL_SHA256SUMS.txt` after all runtime evidence exists.
- Added `Scripts/run_win64_attested_candidate_acceptance.ps1` as the sealed one-command candidate path: it runs the existing technical/rendered acceptance first, verifies the exact summary boundary, then attests and rebuilds the final ZIP so the uploaded archive contains the final manifest instead of a pre-runtime hash snapshot.
- Added a dedicated self-hosted `[self-hosted, windows, x64, unreal-5.8]` attested-candidate workflow that uploads only exact-SHA/version/configuration-bound candidate artifacts and never publishes a Release.

## Changed
- Removed stale hard-coded `0.1.52` package and `0.1.20` release defaults; candidate version must now be explicit and match the exact checked-out project metadata.
- Removed the stale `0.1.14` default from direct `package_windows.ps1` use: omitted versions now resolve from `Config/DefaultGame.ini`, and mismatched explicit versions fail before packaging.
- The package lane now proves the final `SK_GTT_FarmTrailer.uasset` exists after UE import before `package_windows.ps1` may run.
- The reviewed Demo Release lane now rejects candidates without exact-SHA/version authored-trailer import evidence and no longer claims a brittle fixed gameplay-step count in release notes.
- Final candidate integrity is now sealed after runtime and rendered evidence, closing the earlier gap where the package-time `SHA256SUMS.txt` predated later acceptance evidence; the attested lane rebuilds the ZIP and sidecar hash only after final evidence hashing.

## Gate truth
This is a release-engineering milestone that materially reduces the evidence/runner gap required by the five remaining roadmap items. It does **not** claim that UE 5.8 Win64 packaging, packaged EXE smoke, Native Chaos runtime acceptance, authored-trailer visual acceptance or a public Demo Release has actually passed. The new attestation proves identity/integrity only when a qualifying Windows runner actually executes it. Roadmap truth remains 125/130 (96.2%).
