# GTT 0.0.79 — Native Chaos Acceptance Matrix & Runtime Smoke Evidence

## Added

- Fleet-wide Native Chaos acceptance matrix for Rusty Fieldmaster 60, Rattleback 82 and Mulebox 1200.
- One runtime contract now combines canonical wheel configuration, canonical engine/transmission/differential configuration, Physics Asset, active Chaos movement, four valid wheel states and four suspension samples.
- Per-vehicle consecutive healthy-runtime accumulation rather than treating a single good frame as meaningful proof.
- Suspension-travel and peak-ground-contact evidence accumulated during each healthy takeover window.
- `NATIVE_CHAOS_ACCEPTANCE_MATRIX` telemetry every five seconds with the complete acceptance state.
- `NATIVE_CHAOS_SMOKE_READY` evidence after at least 20 consecutive accepted seconds, real ground contact and measurable suspension movement.
- Dedicated 0.0.79 playtest procedure and Project sanity verifier.

## Changed

- Native Chaos closure now has an explicit runtime acceptance matrix suitable for later Unreal/Win64 evidence capture instead of several disconnected setup/runtime log lines.
- A smoke-ready line is deliberately stronger than source validation: it requires sustained live runtime health and suspension activity.

## Validation / limitations

- Roadmap remains **125/130 (96.2%)**. The matrix is instrumentation and runtime gating infrastructure; this repository-only run does not supply genuine UE 5.8 execution evidence.
- `NATIVE_CHAOS_SMOKE_READY` is not equivalent to a packaged Windows demo acceptance. Final demo still requires a real Win64 package launch, runtime smoke test and visual acceptance.
- No full Unreal/Win64 compile or packaged EXE execution was available on the current GitHub runner.
