# GTT 0.0.80 — Win64 Demo Evidence Gate

## Added

- A strict `evaluate_demo_candidate.ps1` gate that binds a packaged Win64 build to its exact Git commit and refuses technical demo readiness unless packaged runtime smoke evidence is `PASS`.
- Fleet-wide packaged Native Chaos proof requirement: the runtime log must contain `NATIVE_CHAOS_SMOKE_READY` evidence for Fieldmaster, Rattleback 82 and Mulebox 1200.
- `DEMO_TECHNICAL_GATE.json` as a machine-readable candidate manifest for later release automation.
- Optional `-RequireVisual` mode requiring a separately reviewed `DEMO_VISUAL_ACCEPTANCE.json`; technical CI cannot silently substitute for rendered visual review.
- Win64 evidence workflow now runs the technical gate and uploads its manifest and packaged runtime log with the candidate artifact.
- Dedicated Project sanity verifier and 0.0.80 playtest/evidence procedure.

## Changed

- Win64 workflow dispatch now defaults to milestone `0.0.80` rather than the stale 0.0.43 label while still passing the selected version explicitly to the packaging helper.
- The Windows evidence pipeline now distinguishes package validation, process-alive smoke, Native Chaos gameplay evidence, and human visual acceptance instead of collapsing them into one ambiguous pass state.

## Validation / limitations

- Roadmap remains **125/130 (96.2%)**. This milestone creates the evidence gate; it does not manufacture evidence that has not been produced by UE 5.8 on Windows.
- Current Project sanity remains Ubuntu source-level verification. A self-hosted Windows x64 runner carrying the `unreal-5.8` label is still required to execute the package workflow.
- No GitHub Demo Release may be created from `DEMO_TECHNICAL_GATE.json` alone. Public demo acceptance additionally requires `DEMO_VISUAL_ACCEPTANCE.json` with `result=PASS` and an actual review of the rendered build.
