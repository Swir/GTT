# GTT 0.1.46 — Packaged Workshop Repair Queue Evidence

## Added

- Added `UGTTWorkshopQueueRuntimeEvidenceSubsystem`, an opt-in deterministic packaged route that starts after the 0.1.44 workshop-hours evidence window and exercises the real 0.1.45 deferred workshop queue.
- The route books a damaged/mobile owned native road vehicle after closing, requires an exact `PersistentVehicleId`, positive request-time locked quote, persisted next-opening schedule and **zero pre-charge**.
- `GTT_WorkshopQueue_01` is loaded back from disk and must preserve schema, exact vehicle ID, locked quote and ready time before the route continues.
- At opening, the exact queued vehicle is deliberately parked away while a different owned native road vehicle is staged at the workshop. The reservation must remain pinned and unpaid, proving a substitute cannot consume another vehicle's reservation.
- The exact vehicle is then staged at the real workshop. Production queue execution must debit the locked quote exactly once, invoke the existing native workshop service, save progress, clear the sidecar and preserve the stable vehicle identity.
- Primary Farm Cargo authority fields are compared across the service so the queue cannot silently transfer/revive cargo, rewind the timer or improve cargo integrity.
- Added `Scripts/evaluate_workshop_queue_runtime.ps1`, producing `WORKSHOP_QUEUE_RUNTIME.json` (`gtt.workshop-queue-runtime.v1`) only from packaged PASS markers and matching production queue logs.
- Added `Scripts/promote_demo_gate_workshop_queue.ps1`; same-SHA schema-14 workshop-hours evidence is required before promotion to demo technical gate schema 15.

## Release pipeline

- The Win64 evidence route now carries `-GTTWorkshopQueueRuntimeScenario`, retains the queue manifest in success/failure artifacts and requires it before complete-candidate validation.
- Candidate technical-gate validation advances to schema 15 only after workshop-hours and workshop-queue packaged evidence both PASS.
