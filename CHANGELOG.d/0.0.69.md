# GTT 0.0.69 — Native Road Crash-Scene AI & Hit-and-Run Escalation

## Added

- Civilian traffic cars now enter a real crash-response state after Native Rattleback 82 / Mulebox 1200 collisions instead of immediately resuming normal route driving.
- Impact victims perform an emergency stop, expose a temporary CAUTION/HAZARD state, and either limp away at reduced speed or remain disabled when vehicle condition falls below the incident threshold.
- Nearby civilian traffic reacts to a crash scene by slowing/stopping and biasing away from the incident origin, reducing pile-up behavior around fresh collisions.
- Native traffic incidents now create a short-lived crash-scene record. Leaving the scene beyond the escape radius within the active window produces a one-time `NATIVE_ROAD_HIT_AND_RUN` escalation through the existing `UGTTWantedComponent`.
- Incident telemetry now records an approximate FRONT/REAR/LEFT/RIGHT impact zone and the number of surrounding traffic vehicles that reacted.

## Changed

- Traffic performance budgeting treats active crash-response vehicles as critical so emergency braking is not throttled by long-distance AI tick reduction.
- Damaged traffic vehicles use the existing shared condition/tire model; no duplicate incident health state was added.
- Hit-and-run heat is additive to, and distinct from, the initial collision crime heat, but remains in the existing wanted/police system.
- Roadmap remains `125/130 (96.2%)`; source-level incident work does not close Native Chaos or Win64 runtime-only tasks.

## Verification

- Added `Scripts/verify_native_road_crash_scene.py` and wired it into Project sanity.
- Added `Docs/PLAYTEST_0.0.69.md` covering victim emergency stop, nearby-traffic response, disabled/limp recovery, hit-and-run escalation and no-duplicate behavior.

## Known limitation / Demo status

This milestone is source/runtime implementation and CI-contract work. It is not proof of a compiled Unreal Engine 5.8 Win64 package. Demo remains blocked until a real Win64 package is built, the packaged executable passes runtime smoke testing, rendered visual acceptance passes, relevant CI is green, and no demo-critical blocker remains.
