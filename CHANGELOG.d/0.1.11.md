# GTT 0.1.11 — Emergency Dispatch Windows & Priority Job Chains

## Added
- Real emergency pickup SLAs for priority logistics. Accepted ROAD `PRIORITY/RUSH/CRITICAL` work now requires the Rattleback to reach Village Parts Depot within a locked 90/70/50-second gameplay window before the existing two-leg delivery timer even begins.
- Priority-chain progression derived from the already-persistent clean logistics streak. Up to three clean ROAD/CARGO jobs grant an earned grace period (+10 seconds per step to urgent ROAD pickup and +5 world-clock minutes per step to urgent CARGO pickup) and a bounded +3% per-step multiplier on genuinely urgent ROAD work.
- CARGO emergency reservations now cap the relationship favor window by the live urgency SLA: PRIORITY/RUSH/CRITICAL uses 40/25/15 world-clock minutes before chain grace. TRUSTED/PREFERRED drivers keep their queue capacity and ordinary hold favors, but trust can no longer turn a critical shipment into a two-hour reservation.
- Dispatcher/contract-desk summaries now expose priority-chain state and both pickup deadlines without replacing the compact world-space interaction prompts.
- `Scripts/verify_emergency_dispatch_chain.py`, `Docs/PLAYTEST_0.1.11.md`, and a dedicated `GTT 0.1.11 emergency dispatch sanity` workflow.

## Changed
- ROAD contract terms are frozen at acceptance: urgency, payout multiplier, pickup SLA, priority label and delivery-time scale cannot silently drift if stock/demand/backlog changes while the driver is heading to the depot.
- Missing an urgent ROAD pickup is a real failed legal contract, so the existing reputation/clean-streak consequence runs and the priority chain is lost. Reaching the pickup radius on the expiry frame wins the handoff before the timeout check to avoid a one-frame edge-case failure.
- ROAD fast-delivery evaluation now uses the actual locked urgency-adjusted delivery window rather than the 185-second baseline denominator.
- STANDARD ROAD jobs remain free of the new chain multiplier. CARGO still receives no hidden priority payout multiplier; its existing capped market multiplier already includes the shared clean streak, while 0.1.11 changes reservation timing instead.
- Existing CARGO stock backing, expiry stock return, backlog consequence, queue capacity, no-double-debit pickup, police handoff locks, vehicle readiness, cargo/parcel damage, and market settlement remain authoritative.
- SaveVersion remains 8. No new mutable chain field is needed: clean streak, market state, backlog and reservation timestamps already persist the inputs required to reconstruct 0.1.11 behavior.
- Roadmap remains exactly **125/130 (96.2%)**. This milestone does not claim any of the five remaining Native Chaos/authored-trailer/real-Win64 gates.

## Verification boundary
- Source sanity verifies the SLA tables, chain bounds, standard-vs-urgent reward policy, locked ROAD terms, actual ROAD pickup timeout/failure path, effective CARGO hold cap, preservation of the 0.1.9 queue and 0.1.10 dispatch contracts, save-schema stability and SWIR Roadmap Style Lock.
- Source verification cannot prove Unreal Header Tool/reflection, C++ linking, rendered timing/handling feel, packaged Windows behavior or visual quality. A real UE 5.8 Win64 build must still compile/package this code and exercise the scenarios in `Docs/PLAYTEST_0.1.11.md`.
- **No demo Release is authorized** by 0.1.11 alone. A verified Win64 Unreal package, packaged-EXE runtime smoke, green relevant Actions, rendered visual acceptance and no demo-critical blocker remain mandatory.
