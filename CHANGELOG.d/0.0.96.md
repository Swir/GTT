# GTT 0.0.96 — Player-Selectable Recovery & Damage HUD

## Added
- Added an explicit player roadside-recovery decision for Native Chaos road vehicles. At wanted 0 a stranded Rattleback 82 or Mulebox 1200 no longer disappears into an automatic tow timer: the player can remain with the vehicle, attempt a limp-home recovery, or authorize transport with `T` / gamepad D-Pad Up.
- Added compact Native road-vehicle HUD presentation driven by the same authoritative breakdown assessment used by workshop/tow economics: condition, tires, body health, damage severity, recommendation, tow quote and repair estimate are visible without debug telemetry walls.
- Added `UGTTRecoveryChoiceEvidenceSubsystem` and a packaged evaluator that prove the complete choice/economy loop with measured runtime state.
- Added a dedicated `Win64 recovery-choice evidence` self-hosted UE 5.8 workflow for 0.0.96. It retains the existing 33-step scenario, then requires the new explicit recovery route and uploads `RECOVERY_CHOICE.json` alongside the normal technical evidence bundle.

## Changed
- Civilian roadside assistance and police custody are now deliberately different systems. Wanted 0 requires player authorization; wanted 1 blocks civilian assistance; wanted 2+ can still trigger automatic police impound because that is law-enforcement custody rather than a voluntary service.
- A tow remains transport only. It charges the quoted tow price and preserves condition, tire and body damage. The player must separately interact with the workshop and pay the separately quoted repair price to restore the vehicle.
- The demo technical gate now requires `gtt.recovery-choice.v1` when `BUILD_INFO.json` identifies version 0.0.96, while older evidence routes remain backward compatible.

## Gameplay impact
+Vehicle breakdowns are now decisions instead of timers. A player who limps a damaged vehicle back to the workshop can save the tow fee; an immobilized player can choose a paid tow and immediately see the economic consequence. Transport does not magically repair damage, so the workshop remains a second, meaningful spending decision.

## Verification / limitations
- Project sanity validates the request API, wanted-aware branching, compact HUD, no-auto-tow rule, deterministic runtime evidence contract, package workflow and unchanged SWIR Roadmap Style Lock.
- Roadmap remains exactly `125/130 (96.2%)`; source checks do not claim a Native Chaos or Win64 acceptance checkbox.
- No UE 5.8 Win64 compile/package, packaged-EXE smoke PASS or visual-acceptance PASS is claimed until a real self-hosted `unreal-5.8` runner executes the workflow and the rendered demo is reviewed.
- Prototype detached-panel geometry is still not final presentation art.
