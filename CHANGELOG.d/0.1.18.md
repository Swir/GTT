# GTT 0.1.18 — Runtime acceptance closure

This milestone closes a gap in the *evidence chain*; it does not close any of the five remaining hardware/runtime Roadmap items.

## Win64 technical gate closure

- The deterministic drivetrain manifest is now mandatory for the demo technical gate. `NATIVE_DRIVETRAIN_SCENARIO.json` can no longer be produced by the workflow and then silently ignored by final candidate acceptance.
- Added `Scripts/evaluate_authored_trailer_runtime.ps1`, which converts the existing authored-rig runtime evidence into `NATIVE_TRAILER_RUNTIME.json` (`gtt.native-trailer-runtime.v1`).
- Authored trailer runtime acceptance requires sustained authored-rig takeover, Native Fieldmaster attachment, two-wheel ground contact, and safe hitch alignment in multiple runtime samples.
- `DEMO_TECHNICAL_GATE.json` moves to schema 6 and now requires both deterministic drivetrain PASS and authored trailer runtime PASS, in addition to the existing Win64 smoke, 33-step gameplay scenario, gameplay smoke, and Native Chaos runtime telemetry.
- The Win64 evidence workflow uploads the trailer manifest in both verified-candidate and failure-diagnostic bundles.

## Acceptance honesty

- This milestone does **not** claim a UE 5.8 Win64 build, packaged EXE smoke, authored trailer asset acceptance, or visual acceptance.
- The Roadmap stays 125/130 (96.2%) and all five runtime/hardware blockers remain open.
- `NATIVE_TRAILER_RUNTIME.json` can only become PASS from real packaged runtime log evidence; source CI cannot synthesize a pass.
