# GTT 0.1.26 — World-Space Pull-Over Guidance & Patrol Lighting

## Gameplay and presentation

- Added `AGTTRangerPullOverMarker`, a physical world-space shoulder target driven by the exact fixed road-stop frame already used by compliance, traffic and ranger staging.
- COMPLY now has an in-world `PULL OVER` target instead of relying only on HUD distance text. The marker is visual-only; it cannot independently grant compliance or mutate Wanted/economy state.
- The marker performs a world-static downward trace before presentation so it follows authored ground height instead of floating at the vehicle pivot height.
- During SEARCH, the floating instruction and chevron are removed and the ground cue is deliberately dimmed to keep the stopped scene readable. FLEE/idle remove the marker entirely.

## Patrol scene polish

- The original code-built warden support vehicle now has paired amber point-light beacons synchronized with its visible roof beacons.
- SEARCH activates a dedicated forward scene lamp so the inspected shoulder area remains legible, especially during the existing night-poaching loop.
- All new lighting remains transient presentation. The patrol actor still owns no garage, SaveGame, Wanted, citation or contraband authority.
- `AGTTRangerDirector` owns exactly one hidden pull-over marker and one hidden patrol support actor, both consuming the shared road-stop subsystem instead of inventing parallel incident state.

## Validation

- Added `Scripts/verify_ranger_world_marker.py` and the dedicated `ranger-world-marker-sanity.yml` workflow; it chains the complete 0.1.25 roadside-scene verifier before checking the new marker/lighting contract.
- Added `Docs/PLAYTEST_0.1.26.md` with world-space, slope/grounding, day/night, SEARCH declutter, traffic, FLEE and regression coverage.
- `Docs/ROADMAP.md` remains 125/130 (96.2%). This source/presentation milestone does not close any of the five remaining Win64/native-runtime acceptance items.

## Demo status

This milestone does **not** claim a Windows demo build. Unreal Engine 5.8 Win64 compile/cook/package, packaged-EXE runtime smoke, native Chaos/trailer evidence and rendered exact-candidate visual acceptance are still required before a Demo Release can be created.
