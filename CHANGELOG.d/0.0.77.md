# GTT 0.0.77 — Native Command Composition & Suspension Runtime Evidence

## Added

- One deterministic final command-composition path for Rusty Fieldmaster 60, Rattleback 82 and Mulebox 1200.
- Same-frame axle/traction sampling exposed by `UGTTNativeAxleTractionSubsystem` instead of letting multiple world subsystems independently overwrite throttle/brake commands.
- Final `throttle / brake / steering / gear` composition in `UGTTNativeDriveDynamicsSubsystem` using the strictest upstream drivetrain and axle safety limits.
- Four-wheel authored suspension runtime evidence from actual Chaos `FWheelStatus::NormalizedSuspensionLength` values.
- `NATIVE_COMMAND_COMPOSITION_EVIDENCE`, `NATIVE_COMMAND_COMPOSITION_LIMIT` and `NATIVE_AXLE_TRACTION_RECOMMENDATION` telemetry.
- Dedicated playtest and Project sanity gate for command ownership, strictest-brake composition and suspension evidence.

## Changed

- The 0.0.76 axle subsystem is now an evidence/recommendation producer for throttle/brake/steering safety instead of a competing movement-input writer.
- Direction interlock, neutral engine braking, hill hold and axle brake assist are merged with `max()` semantics, so a weaker safety request cannot erase a stronger brake request.
- Axle torque cut can only reduce final throttle; it can never restore throttle removed by governor, damage or drivetrain interlock.
- Axle imbalance/traction can only reduce steering authority. It cannot create extra steering or artificial grip.
- The command composer samples wheel/suspension state in the same call that resolves final movement commands, avoiding dependence on world-subsystem tick order for safety decisions.

## Validation / limitations

- Roadmap remains **125/130 (96.2%)** because source-level composition and runtime telemetry contracts are not substitutes for a real UE 5.8 authored-asset runtime acceptance and Win64 packaged smoke test.
- The remaining Native Chaos tasks must stay open until actual Unreal runtime evidence proves the final vehicle rigs and movement setup.
- The current GitHub runner still does not prove a packaged Windows EXE or rendered demo quality; no Demo Release should be created from this milestone alone.
