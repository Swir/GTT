# GTT 0.0.73 — Authored Trailer Runtime Takeover & Wheel-Contact Dynamics

## Added
- New `UGTTTrailerAuthoredRuntimeSubsystem` that moves a valid authored trailer rig beyond passive acceptance into active runtime use.
- Automatic authored-presentation takeover when the skeletal rig satisfies the existing `GTT.AuthoredTrailerRig` contract: Physics Asset, `root`, `wheel_l`, `wheel_r`, `tow_eye` and `axle_center`.
- Greybox trailer visuals remain the safe fallback and are restored automatically whenever the authored rig disappears or becomes invalid.
- Bone-driven left/right wheel ground-contact traces with per-wheel clearance, axle tilt and contact-ratio telemetry.
- Authored axle-centre anti-sway dynamics tied to real trailer load, wheel contact and articulation while towing with the accepted Native Fieldmaster path.
- `tow_eye`-to-`rear_hitch` runtime alignment evidence and authored articulation telemetry.
- Runtime evidence token `AUTHORED_TRAILER_RUNTIME_EVIDENCE` covering presentation takeover, wheel contacts, axle tilt, hitch alignment and stabilization load.
- Dedicated authoring/activation guide and playtest plan for migration of the final original trailer asset.

## Gameplay impact
- A future final skeletal trailer is no longer just validated and then ignored: once valid, it becomes the visible trailer presentation and its authored wheel/axle locations directly feed the towing dynamics.
- Heavy cargo increases stabilizer demand through the existing `GetTowLoadFactor()` path, so the authored runtime layer stays connected to cargo integrity, axle damage and heavy-haul behavior rather than becoming a parallel demo-only system.
- Loss of authored validity restores the proven greybox presentation instead of leaving an invisible or corrupt trailer.

## Validation / limitations
- Roadmap remains `125/130 (96.2%)` because this commit does not contain the final original skeletal `.uasset` and does not provide Unreal 5.8 runtime/render evidence for that asset.
- `Authored skeletal trailer wheel assets and final hitch sockets` therefore remains open until the actual authored asset is committed and proven in Unreal runtime.
- Linux source-level Project sanity cannot replace a UE 5.8 Win64 compile/package/smoke test. No Demo Release should be created from this milestone alone.
