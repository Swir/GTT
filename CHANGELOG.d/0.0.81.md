# GTT 0.0.81 — Packaged Gameplay Smoke Gate

This milestone turns the Win64 candidate pipeline from a process-alive check into a stronger packaged-gameplay evidence gate.

- Added `evaluate_packaged_gameplay_smoke.ps1`, producing `GAMEPLAY_SMOKE.json` from the exact packaged runtime log.
- The hard gate rejects fatal/assert/unhandled-exception signatures and requires sustained Native Chaos smoke-ready evidence for Fieldmaster, Rattleback 82 and Mulebox 1200.
- Runtime/build evidence remains bound to the exact Git SHA; stale evidence from another package cannot qualify.
- Added diagnostic representative-coverage signals for world boot, traffic, NPC, mission and police/wanted systems. These are intentionally diagnostic until deterministic scenario markers are emitted, so the pipeline does not pretend to have tested gameplay that it did not actually drive.
- `DEMO_TECHNICAL_GATE.json` now requires `GAMEPLAY_SMOKE.json: PASS` in addition to package validation, runtime survival and fleet Native Chaos evidence.
- Win64 evidence artifacts now retain `GAMEPLAY_SMOKE.json` alongside the package, runtime log and technical gate.
- Added Project sanity verification for the new evidence contract.

No roadmap checkbox is closed by this source-level milestone. A genuine UE 5.8 Windows runner, packaged execution and visual acceptance are still required before a demo release can be created.
