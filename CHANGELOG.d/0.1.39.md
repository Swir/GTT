# GTT 0.1.39 — Persistent Roadside Dispatch & Save/Load Recovery

## Added
- A transactional `GTT_RoadsideDispatch_01` checkpoint for voluntary emergency patch/tow services that are still in flight.
- Persistence of the exact `PersistentVehicleId`, service mode, request-time locked quote and remaining ETA without duplicating cash or repair authority.
- Exact-ID restore that waits for the real native vehicle + driver to exist after actor recreation instead of binding to a substitute vehicle.
- Farm Cargo compatibility validation: when the primary snapshot has a physical cargo vehicle bound, the roadside checkpoint can only capture/restore that same authoritative vehicle.
- Source verifier, dedicated CI workflow and a 64+ scenario playtest plan for checkpoint creation, reload/rebind, invalidation, cancellation, cargo continuity and regression coverage.

## Changed
- Voluntary roadside dispatch can now survive a session reload as the same transaction. The restored service resumes from the saved remaining ETA and reaches the existing production completion path, which remains the only place that charges the locked quote.
- The persistence layer deletes its tiny sidecar as soon as no live voluntary service remains, preventing completed/cancelled services from resurrecting on a later launch.
- Ambiguous duplicate persistent IDs, police/wanted conflicts, no-longer-eligible vehicles and invalid patch state are rejected without charge instead of being coerced into a service.
- Roadmap truth remains **125/130 (96.2%)**. This source milestone does not close Native Chaos, authored-trailer, Win64 build/runtime or visual acceptance gates.

## Verification boundary
- The new verifier proves source contracts, exact-ID guards, no-economy-mutation restore code, SVG-only progress presentation and deterministic checkpoint wiring.
- This milestone **does not prove** an Unreal Engine 5.8 compile, packaged Win64 executable, packaged save/load runtime smoke test or demo readiness.
- A qualifying Windows x64 + UE 5.8 runner is still required before packaged-runtime evidence or a Demo Release can be accepted.
