# GTT 0.1.29 — Deterministic Packaged Farm Cargo Runtime Exercise

## Runtime vertical slice

- Added `UGTTFarmCargoEvidenceScenarioSubsystem`, an explicit packaged-runtime route that starts after the existing drivetrain and authored-trailer evidence windows.
- The route uses the real Farm Cargo director and terminals: accept a staffed Tier-2 stock-backed contract, load cargo, prove the exact physical vehicle binding, reject a deliberately substituted vehicle at Hill Farm, then complete Hill Farm and North Wood Yard with the original load vehicle.
- Runtime PASS requires positive payout, exactly one cargo-completion history delta, positive logistics reputation gain, a successful post-delivery `SaveProgress`, same-vehicle continuity and cargo-authority cleanup.
- Evidence-only reputation seeding is isolated to the smoke route and the logistics/economy/time baseline is restored after evaluation; no parallel payout, market or save authority was added.

## Win64 evidence hardening

- `smoke_test_windows.ps1` now explicitly enables `-GTTFarmCargoRuntimeScenario` and records that flag in `RUNTIME_SMOKE.json`.
- Added `evaluate_farm_cargo_runtime.ps1`, producing `FARM_CARGO_RUNTIME.json` with schema `gtt.farm-cargo-runtime.v1`.
- Extended the technical smoke window to 200 seconds so the Farm Cargo sequence can execute after the 126–172 second authored-trailer exercise.
- The self-hosted Win64 evidence workflow now evaluates and uploads Farm Cargo evidence; `evaluate_demo_candidate.ps1` requires it before the demo technical gate can pass.
- Added a dedicated source sanity workflow plus playtest coverage for exact-vehicle continuity, wrong-vehicle rejection, payout/reputation/save observation and cleanup.
