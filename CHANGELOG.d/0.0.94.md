# GTT 0.0.94 — Persistent Structural Limp-Home Dynamics

## Added
- Added `UGTTStructuralDriveConsequenceSubsystem`, a runtime layer that converts the existing Native road-vehicle structural snapshot into continuous physical consequences instead of leaving body damage as save data and visual debris only.
- Rattleback 82 and Mulebox 1200 now receive velocity-proportional longitudinal drag from structural severity, asymmetric lateral pull from left/right body imbalance, and additional cooling drag in severe limp-home conditions.
- Added `FGTTStructuralDriveState` with measurable damage severity, drag rate, lateral pull, power retention, steering retention, cooling stress, detached-panel count and limp-home state. It deliberately consumes the authoritative `FGTTRoadBodyDamageSnapshot` rather than introducing another damage save model.
- Added deterministic packaged-runtime proof for three new hard gates: `STRUCTURAL_HANDLING`, `STRUCTURAL_RELOAD_HANDLING`, and `STRUCTURAL_DRIVE_RECOVERY`.

## Changed
- The 0.0.93 save-schema-v5 body/cooling/panel state now has an additional physical driving consequence after reload: the same stored damage must recreate the same limp-home severity, drag, pull and control-retention values within tolerance.
- Paid workshop service must now prove that it removes not only structural save state and detached panels, but also the derived physical drag/pull/limp-home behavior.
- `DEMO_SCENARIO.json` advances to `gtt.demo-scenario.v11` with 33 required evidence steps.
- The self-hosted UE 5.8 Win64 candidate route advances to 0.0.94 and reserves 125 seconds of packaged runtime (`145s` launch timeout) so the complete wanted-4/spike/save-load/structural-limp/workshop chain can finish before evaluation.
- Project sanity now includes a dedicated structural limp-home source/integration verifier while retaining every earlier damage, persistence, roadblock and packaged-demo gate.

## Gameplay impact
A serious front/side crash is no longer just a lower condition number. A damaged Native road vehicle can physically scrub speed, pull toward its weaker side and enter a radiator-driven limp-home state. Saving and reloading preserves the structural cause, so the degraded behavior returns with the vehicle. Paying for a workshop repair removes the body damage and restores normal physical behavior, closing a complete `crash → limp home → save/load → workshop → recovered driving` loop.

## Verification / limitations
- Source/integration verification is provided by `Scripts/verify_structural_limp_home.py` and the full Project sanity workflow.
- Roadmap remains exactly `125/130 (96.2%)`; no Native Chaos/Win64 checkbox is claimed from source checks alone.
- No Unreal Engine 5.8 Win64 compile/package, packaged-EXE smoke PASS or rendered visual acceptance is claimed until a real self-hosted Unreal runner executes the candidate route.
- Detached body pieces remain source-built prototype debris proxies, not final authored vehicle art.
