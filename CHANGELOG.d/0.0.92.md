# GTT 0.0.92 — Spike Damage Persistence & Workshop Recovery

## Gameplay / integration
- Added an opt-in runtime evidence subsystem that continues after the established post-spike escape route and proves the damaged Native road vehicle survives a real `SaveProgress()` / `LoadProgress()` round-trip.
- The persistence proof deliberately repairs the live compatibility mirror before loading, preventing stale in-memory state from masquerading as a successful save/load.
- Native takeover is reactivated after load and must import the same serialized tire/condition damage before the route can continue.
- The recovery half uses the real service-terminal and player-economy path: cash is charged, Native workshop repair runs, tires/condition/fuel/body state are restored, and runtime handling must measurably recover or improve without regression.

## Runtime evidence / CI
- Advanced deterministic demo evidence to `gtt.demo-scenario.v9` with 28 required entries: the previous 26 core steps plus `DAMAGE_PERSISTENCE` and `WORKSHOP_RECOVERY`.
- Added explicit `DEMO_SCENARIO_DAMAGE_PERSISTENCE`, `DEMO_SCENARIO_WORKSHOP_RECOVERY`, and final `DEMO_SCENARIO_DAMAGE_RECOVERY` runtime evidence.
- Advanced the self-hosted UE 5.8 Win64 evidence workflow to 0.0.92.
- Increased packaged-EXE runtime evidence from 20 seconds to 90 seconds with a 105-second launch timeout, so the persistence/workshop route cannot be falsely accepted by a short process-alive smoke check.
- Added a dedicated structural sanity gate for the new save/load/workshop recovery contract.

## Verification boundary
This milestone does not claim that a UE 5.8 Win64 package or packaged EXE was successfully produced on GitHub-hosted runners. Public demo release remains blocked until the exact candidate is packaged on the required self-hosted Unreal runner, completes the runtime evidence route, passes technical and visual acceptance, and has no demo-critical blockers.
