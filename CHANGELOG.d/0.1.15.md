# GTT 0.1.15 — Native Chaos Runtime Telemetry & Drivetrain Acceptance

## Added
- Added live Rusty Fieldmaster 60 Native Chaos telemetry captured directly from `UGTTFieldmasterChaosMovementComponent`: current/target gear, engine/max RPM, forward speed, requested/effective controls, drive-health/grip factors and per-wheel contact/suspension/slip/torque state.
- Added `Scripts/evaluate_fieldmaster_chaos_telemetry.ps1`, which converts packaged runtime log observations into `FIELDMASTER_CHAOS_TELEMETRY.json` only when real drivetrain motion, four valid wheels, ground contact, normalized suspension and non-zero drive torque are observed.
- Added a dedicated 0.1.15 source/evidence sanity gate covering the runtime telemetry contract, Win64 candidate route and truthful roadmap boundary.

## Changed
- The deterministic packaged demo scenario now drives Fieldmaster through its dedicated `ApplyFieldmasterDriveCommand` authority instead of bypassing that layer with generic Chaos input calls.
- The Win64 technical-candidate workflow evaluates Fieldmaster telemetry immediately after packaged EXE smoke, retains the manifest in the candidate artifact and includes the runtime log in failure diagnostics.
- `DEMO_TECHNICAL_GATE.json` now requires a PASS `gtt.fieldmaster-chaos-telemetry.v1` manifest bound to the exact candidate Git SHA before the candidate can pass the existing technical gate.
- Candidate/release defaults move to 0.1.15 while preserving all earlier 33-step deterministic scenario, structural limp-home, damage persistence, workshop, police and fleet regression gates.

## Acceptance boundary
- This milestone makes the runtime test capable of proving dedicated tractor drivetrain/wheel/suspension behavior; source CI alone still does not prove that behavior occurred.
- No runtime-only roadmap checkbox is closed until a real Unreal Engine 5.8 Win64 package executes the candidate workflow and emits matching PASS runtime evidence.
- `Authored skeletal trailer wheel assets and final hitch sockets` remains a separate open content/runtime blocker.
- No Demo Release is authorized without the real Win64 package/runtime evidence plus rendered visual acceptance of the exact candidate.
