# GTT 0.1.15 — Native Chaos Runtime Telemetry & Drivetrain Acceptance

- Added `UGTTNativeRuntimeTelemetrySubsystem`, a packaged-runtime sampler for the accepted Fieldmaster Chaos path. It records live gear/input state, four-wheel validity and contacts, suspension readiness/range, slip, axle load imbalance, traction authority, speed, driver state and attached-trailer tow load from the running Chaos vehicle instead of inferring runtime success from source configuration.
- Added `Scripts/evaluate_native_chaos_runtime.ps1`. A Win64 candidate now receives `NATIVE_CHAOS_RUNTIME.json` only from real packaged runtime evidence. The gate requires matching source SHA, a passing packaged smoke/scenario, Native Physics acceptance, authored wheel-setup evidence, at least two live telemetry samples, four valid wheels, at least two contacts, complete suspension telemetry, non-zero control input, non-neutral gear observation and proven Fieldmaster motion. Any Native Physics fallback makes the gate fail.
- Wired the new runtime manifest into `win64-package-evidence.yml`, including failure diagnostics and the final technical-candidate artifact. `evaluate_demo_candidate.ps1` now requires a passing `gtt.native-chaos-runtime.v1` manifest and emits demo technical gate schema 5.
- Added source-contract regression coverage for the telemetry subsystem, runtime evaluator, Win64 artifact chain, demo candidate gate and SWIR roadmap lock.
- This milestone does **not** claim a successful UE 5.8 Win64 compile/package or packaged EXE smoke on GitHub-hosted source CI. The remaining Roadmap hardware/runtime checkboxes stay open until the self-hosted Unreal runner produces and passes the required evidence.
