# 0.0.64 — Fleet Native Wheel-State & Traction Control

## Added
- Shared `FGTTChaosWheelRuntimeSnapshot` on `UGTTChaosVehicleBridgeComponent`, carrying complete four-wheel Chaos runtime evidence: contacts, slip/skid counts, maximum slip magnitude/angle, normalized suspension length, spring force and drive/brake torque.
- Fleet-level progressive traction intervention derived from real Chaos wheel state plus the existing persistent tire integrity and tire-upgrade state.
- `NATIVE_FLEET_WHEEL_STATE_EVIDENCE` telemetry keyed by persistent vehicle ID so Rusty Fieldmaster 60, Rattleback 82 and Mulebox 1200 can be evaluated through one runtime contract once their native rigs are active.
- Runtime bridge status now exposes `RUNTIME 4/4` contact/risk readiness instead of stopping at static rig/wheel/powertrain acceptance.
- Dedicated `PLAYTEST_0.0.64.md` and Project sanity verifier coverage.

## Changed
- Native throttle routing now applies a wheel-state throttle limit when sustained runtime risk exists; stronger slip/skid/contact loss can add bounded brake assist and reduce steering authority.
- Fleet native response consumes the existing `AGTTVehicleBase` condition/fuel/tire/tuning state instead of adding duplicate gameplay or save variables.
- Fieldmaster keeps its deeper tractor-specific stability systems for trailer sway, load transfer, terrain/hill response and rollover protection; the bridge supplies a common baseline for all native fleet vehicles.

## Limitations / Next
- Rattleback 82 and Mulebox 1200 still need real authored skeletal/physics assets and an Unreal runtime before their bridge can honestly enter native driving state.
- Source-level sanity does not verify an Unreal Engine 5.8 Win64 compile/package/runtime smoke test.
- Roadmap remains 125/130 (96.2%); Native Chaos and Win64 runtime checkboxes stay open until genuine packaged runtime evidence exists.
