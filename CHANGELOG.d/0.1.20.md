# GTT 0.1.20 — Rendered visual evidence and exact-candidate Demo Release gate

This milestone closes the release-process gap between technical packaged evidence and the visual quality requirement. It does **not** claim that a rendered Win64 candidate has already passed.

## Deterministic rendered evidence

- Added `UGTTDemoVisualEvidenceSubsystem`, enabled only by `-GTTVisualEvidence`, with five deterministic capture points across the existing playable evidence route: world/gameplay, law pressure, native vehicle, loaded trailer and final HUD overview.
- Captures use Unreal Engine's viewport screenshot path with Slate/HUD enabled and write exact scene filenames into a dedicated evidence directory.
- Added a second packaged run that intentionally does **not** use NullRHI. It runs offscreen at 1280×720 with the deterministic demo scenario and preserves a separate rendered runtime log.
- `evaluate_demo_visual_evidence.ps1` verifies all five PNGs, minimum resolution/size, non-flat sampled luminance, sampled color variation, scene markers and frame diversity, then writes `DEMO_VISUAL_EVIDENCE.json`.
- Automated image checks are explicitly not treated as aesthetic approval; the manifest keeps `human_review_required=true`.

## Exact-candidate release publication

- `win64-package-evidence.yml` now appends the rendered visual run and its screenshots to the same exact-SHA candidate that already must pass preflight, UAT package, packaged smoke, 33-step gameplay, Native Chaos, deterministic drivetrain and loaded authored-trailer gates.
- `release-windows.yml` is now a publication workflow rather than a second weaker rebuild path. It downloads a previously successful candidate by `candidate_run_id`, verifies that the source workflow succeeded for `main` at the exact requested SHA, validates the candidate ZIP hash, and never rebuilds the game after review.
- A reviewer must inspect the already-produced screenshots first, explicitly attest `visual_review_passed=true`, and provide review notes. `write_demo_visual_acceptance.ps1` binds the reviewer, screenshot hashes and visual-evidence manifest hash to the exact commit.
- The full technical gate is re-evaluated with `-RequireVisual` before an optional prerelease can be created. Manual runtime-smoke confirmation is not accepted as a substitute for evidence.

## Acceptance honesty

- No Demo Release is created by this source milestone.
- No rendered screenshots, Win64 UE 5.8 package, packaged runtime smoke or human visual approval are claimed until the qualifying self-hosted runner actually produces them.
- Roadmap progress remains 125/130 (96.2%) because all five runtime/hardware blockers are still open.
