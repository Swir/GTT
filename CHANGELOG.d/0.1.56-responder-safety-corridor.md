# GTT 0.1.56 — Responder Safety Corridor

- The 0.1.55 county ROAD SERVICE responder now deploys four visible runtime-built safety cones when it reaches an active severe civilian incident; the cones use the engine-local `/Engine/BasicShapes/Cone.Cone` mesh and disappear with the responder.
- Added `UGTTRoadsideSceneSafetySubsystem`, a subordinate scene-safety layer that detects a parked responder and asks nearby ambient drivers to use the existing traffic incident reaction path.
- Traffic yielding is bounded to a 1,800 cm scene radius, excludes the inner 320 cm recovery pocket, and is cooldown-limited per vehicle to one pulse every 4.5 seconds so the scene does not create an unbounded stop loop.
- Per-car yield history is now scoped strictly to the current physical responder scene: responder replacement and corridor teardown clear cooldown history so a fresh incident cannot inherit suppression or accumulate stale scene state.
- Disabled vehicles, active player roadside assistance, county responder scene authority and ranger/warden road-stop traffic are never overridden by the safety corridor; warden traffic-control priority remains authoritative.
- The safety subsystem has no economy, repair, Wanted, fine, mission or dispatch ownership. Existing 0.1.54 incident authority, 0.1.55 no-payout responder recovery and 0.1.53 player payout authority remain unchanged.
- Expanded the playtest matrix to 52 cases, including corridor teardown/replacement lifecycle coverage; deterministic source-contract verification and dedicated GitHub Actions regression gate remain authoritative for source CI.
- Verification boundary: source-contract/CI only. This milestone does not claim Unreal Engine 5.8 Win64 compile/package, packaged EXE smoke, runtime evidence, visual acceptance or demo readiness.
