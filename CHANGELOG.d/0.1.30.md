# GTT 0.1.30 — Persistent Farm Cargo Recovery & Save Integrity

## Mid-route cargo recovery

- Farm Cargo now writes its active route stage, timer, cargo integrity, locked payout/market multipliers, route tier, reserved units, commodity/priority labels and police-incident flag into the existing primary `GTT_Prototype_01` snapshot.
- `UGTTFarmCargoAuthoritySubsystem` persists the stable `PersistentVehicleId` of the vehicle actually loaded at Feed Depot and can rebind a replacement actor with that exact ID after save/load, garage recovery or actor recreation.
- Recovery never falls back to the nearest vehicle. If the exact cargo vehicle is unavailable, buyer handoff remains blocked until that same persistent vehicle returns.
- Rebound Mulebox actors regain their cargo load factor, so restored Tier-3 bulk loads keep the intended handling penalty instead of becoming visually/physically empty after reload.
- ReachPickup, post-pickup and Hill Farm relay transitions now create explicit save checkpoints. Extended routes can therefore resume at North Wood Yard without re-reserving depot stock or repeating the first handoff.
- Idle/completed/failed snapshots clear the persisted cargo-vehicle identity so an old load cannot leak into the next contract.

## Primary save hardening

- Fixed a legacy `AGTTGameMode::SaveProgress()` path that still created a fresh SaveGame and stamped it as schema v3. That path could erase newer v8 logistics/unified fields when unrelated gameplay called save.
- `SaveProgress()` now updates the existing primary v8 snapshot when present, preserves newer fields, advances the unified revision and captures current logistics plus active Farm Cargo state before writing the slot.
- `LoadProgress()` restores logistics first, then Farm Cargo route state, then exact physical cargo authority, preventing stock duplication and wrong-vehicle reassignment during recovery.
- The v8 format remains additive; existing profiles do not require a destructive migration or a new parallel save slot.

## Verification

- Added `verify_farm_cargo_recovery.py` with guards for stable-ID-only rebinding, route/authority capture ordering, v8 non-downgrade behavior, protected Roadmap math and README PRO v2 preservation.
- Added the dedicated `GTT 0.1.30 Farm Cargo recovery sanity` workflow, which also runs the 0.1.28 authority, 0.1.29 packaged-runtime and SWIR Progress SVG regressions.
- Added `PLAYTEST_0.1.30.md` covering start/pickup/relay checkpoints, exact-vehicle restoration, missing-vehicle recovery, wrong-vehicle rejection, garage/tow actor recreation, no duplicate stock/payout and completion/failure cleanup.
