# GTT 0.0.89 — Native Roadblock Runtime Evidence Gate

## Added
- Packaged demo evidence now requires a measurable `ROADBLOCK_SPIKE_CONSEQUENCE` from the `NATIVE_CHAOS` path for Rattleback 82 or Mulebox 1200.
- The evaluator parses vehicle identity plus tire integrity before/after and rejects zero or inverted tire deltas.
- `DEMO_SCENARIO.json` advances to schema v6 and records the Native spike vehicle and measured tire degradation.
- Win64 evidence workflow advances to 0.0.89 and explicitly names the Native roadblock consequence gate.

## Gameplay / release impact
The technical candidate can no longer pass merely because a roadblock exists and Native spike support is present in source. A real packaged runtime must now produce evidence that a Native Chaos road vehicle actually received a tire consequence from the police roadblock path.

## Verification boundary
This milestone strengthens runtime acceptance but does not manufacture evidence. If the packaged scenario does not physically produce a Native spike contact, the Win64 candidate correctly fails. Source sanity is not a substitute for the UE 5.8 Win64 package/runtime/visual gates required for the first public demo.
