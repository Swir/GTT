# GTT 0.1.5 — Rural Dispatchers, Depot Stock & Contract Rotation

## Added
- Persistent rural CARGO market state for Feed Depot stock, Hill Farm demand, North Wood Yard demand, and the active commodity rotation.
- Deterministic daily restock/demand refresh driven by the existing world day plus real logistics history; current rotation cycles through original `ANIMAL FEED`, `SEED PALLETS`, and `FARM PARTS` loads.
- Actual scheduled logistics workers at the existing Feed Depot, Hill Farm, and North Wood Yard handoff terminals. Dispatchers follow the same 07:00–17:30 rural work shift as the existing citizen schedule and leave their work posts outside that window.
- Load reservation and settlement: accepting a CARGO contract consumes depot inventory immediately, successful delivery satisfies destination demand, and failed/destroyed cargo remains lost while buyer demand stays open.
- Contract Board stock/demand planning line plus explicit no-load state when the current depot inventory or destination demand cannot support another contract.
- Dedicated `Scripts/verify_rural_dispatch_stock.py` sanity gate and `Docs/PLAYTEST_0.1.5.md` milestone playtest.

## Changed
- The CARGO payout multiplier now includes bounded stock-versus-demand pressure and commodity rotation while preserving the existing 1.38x maximum market multiplier.
- Accepted CARGO inventory is saved immediately, so save/reload cannot duplicate reserved depot stock. The existing save schema remains version 8 because the added fields are backward-compatible additive defaults for existing v8 profiles.
- T1/T2/T3 CARGO chains now display the exact reserved commodity and unit count in objectives/messages, then update the same persistent market that the board displays.
- The rural logistics board now answers both questions that matter before a run: what is available at the depot, and which destination still needs it.
